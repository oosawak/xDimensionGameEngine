# xDimension Game Engine 
**[確認用サイト](https://oosawak.github.io/xDimensionGameEngine/)**

**現行バージョン：v0.0.20**  |  **開発段階：技術デモ／ゲームエンジン試作**

xDimension Game Engineは、**2Dのアニメーションキャラクターと3Dの町・地形を組み合わせる、ブラウザ向け2D3Dゲームエンジンの試作**です。Three.jsでワールドを描画し、プレイヤーの移動・屋外衝突・地面の高さなどをWebAssembly（WASM）で処理します。PCとスマートフォンの両方から操作できます。

ゲーム制作の土台として、町・家の内装・複数マップ・時間と季節・NPC・パズルを、実際に歩き回れるサンプルワールドに組み込んでいます。現時点では**汎用マップエディターや完成したRPG制作環境ではなく、拡張中のエンジンとデモ**です。

## できること

| 分野 | 現在の機能 |
|---|---|
| 2Dキャラクター | 待機・歩行・走行・ジャンプ・攻撃の5動作。新画像／旧画像の切り替え、動作別倍率・位置調整 |
| キャラクター画質 | Pixel Art ON/OFF、処理解像度64〜512px（標準160px）、SPRITE INFOで元画像・処理解像度・推定展開量を確認 |
| 3Dワールド | 建物、樹木、高低差、階段、坂道、橋、川、地形の当たり判定とカメラ演出 |
| マップ | 連結した3エリアを移動。町の玄関から室内へ出入りでき、家具との衝突や室内カメラ調整にも対応 |
| 時間・季節 | ゲーム内時計（標準12倍）、昼夜と春夏秋冬、季節による照明・草木・パーティクル表現 |
| NPC | サンプルNPC 4人の時間帯に応じた行動・表示（会話AIや汎用経路探索は未実装） |
| パズル | 2個の木箱を押して2つのスイッチを作動させる試作パズル。WASMの衝突判定と状態保存に対応 |
| 描画 | Three.jsによるWebGPU優先・WebGLフォールバック。被写界深度などの2D3SD像設定 |
| 配布 | C-WASMと使用画像を埋め込んだ単体 `index.html`。Three.jsライブラリはCDNから取得 |

### サンプルマップ

- **MAP 01**：石畳の村・こもれび街道・青葉の町。家への出入り、東門への道、押し箱パズルを体験できます。
- **MAP 02**：霧深い山岳街道。森・起伏・川と木橋を通って次の町へ進みます。
- **MAP 03**：翠峰の町。別の町並みと玄関・室内への出入りを試せます。
- **UNDERWATER DEMO**：海面から深度240mまで連続して潜る横視点2.5D試作。画面左下の仮想スティックをドラッグして自由な方向へ泳ぎ、倒す量で速さを調整できます。PCはA/D・W/Sでも操作可能。Shift／RUNで加速、Eで発光アイテムを採集、FまたはLIGHTでライトを切り替えます。酸素制限・敵AI・洞窟の斜め見下ろしは未実装です。

マップは出入口で切り替わり、時計と季節は継続します。現状はマップごとに専用のThree.js描画コードがあり、JSONだけで任意のマップが生成される仕組みではありません。

## 実行方法

`index.html` を対応ブラウザで開きます。**Three.jsは外部CDNを利用するため、インターネット接続が必要**です。WebGPUが使えない環境ではWebGLにフォールバックします。WebGPUを確実に利用する場合はHTTPSまたはlocalhost上で動かしてください。

基本操作：

| 操作 | PC | スマートフォン |
|---|---|---|
| 移動 | WASD／方向キー | 画面の方向ボタン |
| 走る | Shift＋移動 | RUN |
| ジャンプ | J | JUMP |
| 攻撃 | K／Space | ATTACK |
| 家に入る・出る／木箱を押す | 対象の近くでE | 対象の近くに表示されるEボタン |
| 設定 | 右上の設定ボタン | 右上の設定ボタン |

設定パネルの **UNDERWATER DEMO / 水中探索を開始** から起動できます。街へ戻るボタンで通常デモに復帰します。

水中背景は、波打つ3D海面、奥行き3層の岩壁、棚状の岩礁、海底、揺れる海藻・珊瑚・魚群で構成しています。海面から離れるほど太陽光が弱まり、青い霧が遠景を覆います。泡は固定プールで上昇し、岩壁はInstancingで描画します。スマホ幅では魚・海藻・粒子の数を減らします。環境素材はコードで生成しており追加の外部素材はありません。

遊泳面の金色の魚12匹は、近づくと自動で狙い、約0.7秒間隔で水中弾を発射します。射撃ボタンは不要です。命中すると捕獲数が増え、魚と採集物の取得状態は街へ戻っても同一プレイ中は保持されます。背景の魚は観賞用です。上下移動は従来の1.6倍に調整しています。

設定パネルの **水中の移動速度** で75〜250%に調整できます（標準100%、ブラウザに保存）。上下・左右の加速と最大速度へ反映され、RUNの加速も併用できます。自動射撃の開始距離は従来の8から3.5ワールド単位へ短縮し、魚に近づいてから撃つようにしています。

魚の捕獲には3発の命中が必要です。魚の上のゲージで残りの耐久値を確認でき、途中で離れても与えたダメージは同一プレイ中保持されます。捕獲数は3発目が命中したときだけ増えます。

水中物理はJavaScriptの独立モジュールです。描画上の鉛直座標は `Y = -depth × 0.28`、遊泳面は `Z = 0.75`。岩礁・岩棚の上面・海底には、表示メッシュのワールド変換済み三角形から生成する当たり判定があります。身体の縦カプセルを3球で近似し、移動を小刻みに判定して高速時のすり抜けを抑え、軸別の解決で壁沿いに泳げます。海藻・珊瑚は装飾です。遊泳面から離れた前景・背景は移動を妨げません。

当たり判定の三角形は初回入水時にキャッシュし、メッシュごとの範囲で候補を絞ります。C/Rustの既存APIは変更していません。別WASMへ移す場合は、三角形データ・カプセル座標・`resolveSwimMotion`／`setCollisionQuery` が境界になります。今回は追加のWASMビルドは不要です。

木箱パズルは設定の **PUZZLE → パズル広場へ移動** から試せます。青葉の町の東門は、中央から北側の横道（Z≈75）を東へ進む経路にあります。

## キャラクター画像・画質の設定

設定の **SPRITES** で使用素材を「新画像・高解像度」と「旧画像」から選択できます。読み込む素材は選択中の5動作を基本とし、素材の切り替え時に読み替えます。キャラクター全体の表示倍率は**標準55%／調整範囲25〜150%**です。ジャンプや攻撃などの動作別調整は別に行えます。

**Pixel Art OFF** は高精細表示、**ON** は選択した処理解像度へ縮小しドット絵風に表示します。解像度を64〜512pxから選び、詳細は **SPRITE INFO** で確認できます。表示されるテクスチャ容量はRGBA換算の概算で、GPU全体の実測使用量ではありません。

### 使用素材・クレジット

**プレイヤー画像は [haruka_apps](https://github.com/harukaappscreate/)　さんにお借りしています。**

「新画像・高解像度」に使うプレイヤースプライト素材です。提供元の表記を尊重し、素材の著作権・再配布可否・商用利用条件は、利用する際に**素材提供者が定める条件を別途確認してください**。本リポジトリへの同梱は、第三者への無制限な再配布許諾を意味しません。

## 技術構成

- **表示・操作**：HTML／CSS／JavaScript、Three.js（WebGPU／WebGLフォールバック）。UI、ワールド表示、キャラクター・季節演出、室内の簡易制御を担当。
- **物理・座標**：C → WebAssemblyを現行ビルドで利用。移動、屋外の衝突、地形高さ、ジャンプ、木箱の押し操作を処理。
- **代替エンジン実装**：Rustの同等APIソースを `src/lib.rs` に保持（Rust版の実コンパイル・描画の完全な動作一致は未検証）。
- **ゲームデータ**：マップ定義、当たり判定、パズル、スプライト管理用のJSONと、衝突用の自動生成ソース。
- **アセット**：元画像PNG→ `tools/pack_sprites.py` でWebPアトラスへ変換し、ビルド時にBase64文字列としてHTMLに埋め込み。

## 開発・変更の手順

**UI文字列だけを修正する場合**は、原則 `index.template.html` を編集し、`./build.sh assets` で `index.html` を再生成すれば十分です。**配布用 `index.html` は生成物のため、直接編集だけで済ませないでください。** 次のような変更では、ほかのファイルも更新します。

| 変更したい内容 | 主な編集先 |
|---|---|
| UIや表示・描画 | `index.template.html`、必要に応じて `src/*.mjs` |
| 移動・衝突・ジャンプ・パズル判定 | `src/engine.c`／`src/lib.rs`、JSON、生成ツール、テスト |
| キャラクター画像・アニメーション | `assets/characters/`、スプライトJSON、`tools/pack_sprites.py` |
| ゲーム内容やマップ | `assets/*.json`、`src/*.mjs`、生成ツール、テスト |
| 文書・開発履歴 | `README.md`、`CHANGELOG.md`、`NEXT_STEPS.md` |

### ビルド

Mac／Ubuntuを想定。C版は `clang`、Python 3、Pillow（`python3 -m pip install pillow`）を使用します。Rust版にはRust・Cargo・`wasm32-unknown-unknown`ターゲットが追加で必要です。

```bash
./build.sh c       # C-WASMをコンパイルし、配布用index.htmlを再生成
./build.sh assets  # 既存WASMと画像を利用してHTMLを再生成
./build.sh rust    # Rust-WASMをビルドしてHTMLを再生成（任意）
```

`assets` モードで当たり判定データがWASMより新しいと、再コンパイルを要求します。マップや物理データを変更した場合は `./build.sh c` を使ってください。

### テスト

```bash
# Node.jsとPythonが利用できる環境で実行
for t in tests/*.mjs; do node "$t" || exit 1; done
for t in tests/*.py; do python3 "$t" || exit 1; done
```

テストは物理・マップ・季節・UI構成などを確認します。ただし、**実機GPU描画とモバイル操作の見え方をすべて保証するものではありません**。WebGPU/WebGLの実画面検証は別途必要です。
